# Как защищать DashFood на Endterm

## Что готово и что нужно дописать самим

Работают клиентское меню, корзина, заказы, статусы, вход сотрудника,
редактирование/отключение товаров, PostgreSQL и три графика в Insights.
В базе есть 120 синтетических заказов для повторяемого анализа.
Проверки и скриншоты лежат в output/evidence.

Участники: Artur (UI Designer), Adiyat (Analyst / Developer), Erdaulet (Researcher / Presenter).
Критерии подтверждены командой: viewing the menu, adding products to the cart, placing an order.

До сдачи внесите названия группы и команды; настоящие результаты минимум трёх внешних тестировщиков;
три замера Fast 4G; замечания преподавателя Stage 1 и ответы на них;
реальное распределение работы. Эти сведения нельзя достоверно придумать.
R11 на прикреплённом изображении обрезан; реализовано отключение товара,
поскольку в видимой проверке написано Disable test product. Сверьте оригинал.

## Запуск перед защитой

1. Запустите Docker Desktop.
2. В корне проекта: `powershell -ExecutionPolicy Bypass -File .\setup.ps1`.
3. Откройте http://localhost:4000. Вход сотрудника: admin; пароль в корневом .env.
4. `docker compose ps`: db и app должны быть healthy.
5. HTTPS: `docker compose --profile https up -d https`, затем https://localhost.
   Первый локальный сертификат нужно доверить по инструкции README.
6. В DevTools Network покажите запросы /api/products и /api/orders.
7. Откройте терминал с `docker compose exec db psql -U cafe -d cafe`.
8. Держите доступным ваш demo video из Assignment 4. Новое видео здесь не создано.

## Live demo: что нажимать

1. Откройте Menu. Укажите категории, поиск и цены в тенге (R1–R2).
2. Добавьте Cheeseburger и Cola (R3). Откройте Cart.
3. Увеличьте Cheeseburger до 2 (R5), удалите Cola (R4), объясните сумму.
4. Place order: появляется номер в My orders (R6–R7).
5. Staff orders: войдите; найдите новый номер (R8), Accept order (R9).
6. Вернитесь в My orders: обновление не позднее 8 секунд. Покажите Preparing.
7. Manage menu: отредактируйте цену тестового товара (R10), Disable (R11).
   Вернитесь в Menu: товара нет. Не отключайте позицию, нужную другим участникам.

9. В psql: `SELECT id,total,status,created_at FROM orders ORDER BY id DESC LIMIT 3;`
   Затем запрос из docs/ANALYSIS.sql. Это доказывает реальное хранение данных.

## Короткие ответы на возможные вопросы

**Где хранится заказ?** В orders и order_items PostgreSQL. Корзина до оформления
хранится в браузере; оформленный заказ сохраняется сервером в транзакции.

**Почему клиент не может подменить цену?** API принимает productId и qty.
Цену получает из products, итог считает сам. Проверка есть в test-api.mjs.

**Как защищена админка?** Пароль хранится как bcrypt hash. При входе выдаётся
JWT на 8 часов. Защищённые endpoints проверяют подпись и role=admin.
Неверный вход отклоняется, есть ограничение попыток. При выходе токен удаляется.

**Почему два графика столбчатые, один линейный?** Столбцы сравнивают товары
и часы; линия показывает изменение выручки во времени. Подписи и единицы видны.

**Что доказывают тестовые данные?** Работу SQL, API и визуализации. Они не
доказывают реальные предпочтения посетителей или реальный пиковый час.

**Как обновить группировку?** Вместо часа сгруппируйте по дате:
`SELECT (created_at AT TIME ZONE 'Asia/Qyzylorda')::date AS day,COUNT(*) FROM orders GROUP BY day ORDER BY day;`

**Почему график может измениться после проверки?** Live demo создаёт новые
заказы. Фильтр `is_demo = TRUE` отделяет 120 исходных записей от новых.

**Как работает smart-функция?** Сейчас это правило: 5 + 3 × число заказов
New/Preparing, максимум 60 минут. Это демонстрационная оценка, не модель ИИ
и не проверенный прогноз. Физическое IoT-расширение описано в отчёте.

**Какие ограничения?** Самовывоз и оплата в кафе; внешнего платёжного сервиса нет.
История клиента привязана к этому браузеру; номер позволяет прочитать состав
и статус заказа, поэтому персональные данные клиентов не собираются. Для реального
кафе нужны непрозрачные tracking-токены, учётные записи, резервное копирование,
проверка нагрузки и измеренный uptime. Не обещайте то, чего нет.
