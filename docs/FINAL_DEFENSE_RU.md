## Запуск перед выступлением

Из корня проекта: `npm run setup`, затем `npm run review`. В Windows можно
открыть StartPreview.cmd. Адрес: http://localhost:4000. Не закрывай терминал.
Логин сотрудника admin, пароль ADMIN_PASSWORD в .local/review-env.json.
Не показывай этот файл на записи или проекторе. Гость работает без регистрации.

https://localhost:4443 использует самоподписанный сертификат: соединение
шифруется, но браузер не доверяет сертификату автоматически. Это не публичный
сертификат и не доказательство готового облачного развёртывания.

## Как устроен заказ

Браузер передаёт productId, qty, имя и ключ повторной отправки. Сервер проверяет
типы и ограничения, начинает транзакцию и блокирует этот ключ. Цену читает из
products. Создаёт orders и order_items, затем COMMIT. Ошибка вызывает ROLLBACK.
Одинаковые параллельные запросы возвращают один заказ. Секретный ключ отслеживания
сохраняется в браузере, в базе хранится его хеш. Один номер чужого заказа не открывает.

## Репетиция живого изменения

Изменить правило количества: найди проверки qty в API, лимиты reducer в store.tsx
и disabled у кнопки в CartPage.tsx. Объясни, почему одной проверки в интерфейсе мало.
Изменить запрос аналитики: например, добавить исключение Cancelled к почасовому
COUNT. Объясни, как это меняет смысл метрики, а не только вид диаграммы.
Добавление нового поля требует UI, типа, payload, серверной проверки, SQL-колонки,
записи и чтения. Сначала репетируй в отдельной ветке и откати пробный вариант.

## Короткие ответы

- Где данные? На этом ноутбуке в .local/postgres; в Docker - volume на хосте.
  Система не использует RDS/S3 в текущем показе. Для реальной эксплуатации нужно
  отдельно подтвердить место размещения, правила хранения и требования к персональным данным.
- Где граница безопасности? Публичное меню и checkout; секрет квитанции для чтения
  собственного заказа; JWT для всех действий сотрудника; база не доступна браузеру.
- Что сломается при 10 тысячах пользователей? Неограниченная выдача всех заказов и
  запросы агрегатов создадут нагрузку. Нужны измерения, пагинация и план мощности.
- Реальный ли IoT? Нет физического датчика. Есть правило min(60, 5+3*очередь).
- Доказаны 99%? Нет, конфигурация перезапуска не является замером uptime.
- Почему нет React Native/AWS? Фактический scope покрывает адаптивный браузерный
  интерфейс и локальную демонстрацию; схема показывает именно реализованное.
