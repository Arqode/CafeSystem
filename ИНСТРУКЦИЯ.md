# DashFood: запуск и защита

> Эта инструкция относится к Stage 2. Для финальной версии смотри [README.md](README.md)
> и [docs/FINAL_DEFENSE_RU.md](docs/FINAL_DEFENSE_RU.md): они содержат новый запуск без
> Docker, правильные критерии из Stage 1 и актуальный сценарий защиты на 8-10 минут.

Пройди файл сверху вниз. Сначала запусти сайт, затем один раз повтори показ.

## 1. Запуск на твоём Mac

1. Открой Docker Desktop и дождись, пока он запустится.
2. Открой папку `cafe_ict` в VS Code → Terminal → New Terminal.
3. Вставь две строки и нажми Enter:

```sh
cd /Users/arthur/Desktop/cafe_ict
bash setup.sh
```

Первый запуск скачивает и собирает проект. Дождись сообщения **Готово**.
Открой **http://localhost:4000**. Это единственный адрес для обычного показа.

Вход во вкладке **Staff orders**: логин **admin**. Пароль выводится в терминале
после запуска и сохранён в корневом `.env`, строка `ADMIN_PASSWORD=`.
Старый `admin123` к этой версии не относится. `.env` не показывай на записи.

Сайт и база работают в Docker в фоне: терминал можно закрыть.
Повторный запуск — та же команда `bash setup.sh`; имеющаяся база сохраняется.
Остановить сайт и базу, сохранив данные:

```sh
docker compose stop
```

Если не открылось:

```sh
docker compose ps
docker compose logs --tail 40 app db
```

`app` и `db` должны быть запущены, после ожидания — healthy. Если написано,
что порт 4000 занят, найди занявшее его приложение; базу удалять не нужно.
Не выполняй `docker compose down -v`: это удаляет данные проекта.

**Для Windows у другого участника:** вместо `bash setup.sh` в PowerShell из
папки проекта выполнить `powershell -ExecutionPolicy Bypass -File .\setup.ps1`.
На Mac команда `powershell ...` не нужна. Node.js и npm на Mac для Docker-запуска не требуются.

## 2. Что это за проект — запомни три части

**React** показывает страницы и собирает действия пользователя.
**Express API** принимает запросы, проверяет вход, цены и количество.
**PostgreSQL** хранит товары и оформленные заказы.

Путь заказа: **браузер → API → PostgreSQL → ответ с номером заказа**.
В этой версии клиент и сотрудник работают с одной базой. Это отличается от
старого браузерного демо. При обычном Docker-запуске включён настоящий API.

English: “DashFood is a café pickup ordering system. Customers place orders,
and staff update their status. Both use the same PostgreSQL database.”

## 4. Сайт — показ по кнопкам, около двух минут

1. **Menu:** категории, поиск, цены в KZT. Добавь Cheeseburger и Cola.
2. **Cart:** увеличь Cheeseburger до двух, удали Cola. Итог при цене 2500 — 5000 KZT.
3. **Введи имя в Your name** — без него заказ не отправится. Нажми **Place order** и покажи номер в My orders. Запомни свой номер: он каждый раз новый.
4. **Staff orders:** войди, покажи имя рядом с этим же номером → Accept order → Mark as ready.
5. **My orders:** покажи READY. Пока страница открыта, она опрашивает данные раз в 8 секунд.
6. **Manage menu:** создай отдельный Test Tea → измени цену → Disable.
   В Menu отключённый товар не показывается. Не отключай товар, нужный для остального показа.
7. **Insights:** открой графики, объясни один из них.

English: “I add products, check the quantity and total, and place the order.
Staff receive the same order and mark it as ready. The customer sees the updated status.”

## 5. Как показать настоящую базу

В терминале VS Code, находясь в папке проекта:

```sh
docker compose exec db psql -U cafe -d cafe
```

Дальше вставляй по одной команде:

```sql
\pset pager off
\dt
SELECT id, name, price, active FROM products ORDER BY id;
SELECT id, customer_name, total, status, created_at FROM orders ORDER BY id DESC LIMIT 3;
```

Покажи в последнем запросе номер заказа, который только что создал на сайте.
Это доказывает запись в базу. Выход из PostgreSQL: `\q`.

Связь: **orders — один заказ; order_items — его позиции**.
`order_items.order_id` ссылается на `orders.id`. В позиции сохраняются название
и цена на момент заказа: последующее изменение меню не должно менять старый чек.
`orders.customer_name` хранит имя для выдачи заказа; его видит сотрудник. Старые заказы без имени имеют подпись Name not provided. `users` хранит учётные записи сотрудников и хеши паролей, `products` — меню. Клиенту регистрация не нужна.

English: “This is the order we just created. It is stored in PostgreSQL.
The order_items table stores its individual items.”

Для всех аналитических запросов сразу, из обычного терминала, не из psql:

```sh
docker compose exec -T db psql -U cafe -d cafe < docs/ANALYSIS.sql
```

Это новая база внутри Docker. Старая локальная `cafe_db` из прошлой версии для этого запуска не используется.

## 6. Графики и картинки — что объяснить

**Insights:** популярные товары — сравнение количества; выручка по дням —
изменение во времени; заказы по часам — распределение нагрузки.
Графики строятся из SQL. Изначальные 120 заказов искусственные, помечены `is_demo=true`.
Новые заказы меняют показатели. Это пример анализа, а не реальные продажи кафе.

**Фото:** большие исходники уменьшили и сохранили в WebP.
`srcSet` даёт браузеру выбор размера, `loading="lazy"` откладывает загрузку
непервых фото, `alt` описывает изображение для экранного диктора.
SVG подходит для логотипа и иконок: остаётся чётким при увеличении.
JPEG/WebP с потерями уменьшают вес за счёт части деталей; PNG сохраняет пиксели без потерь.
Источники фото — `web/public/media/provenance.json` и Image credits на сайте.

English: “We resize photos and use WebP to reduce file size. Responsive sizes
help the browser choose a suitable image. Alternative text describes the photo.”

Не цитируй старые проценты ускорения как замер этой версии. Если нужен Fast 4G:
Chrome → DevTools → Network → Disable cache → Fast 4G → перезагрузка.
Для проверки требования «меньше 2 секунд» сделай три замера и посчитай среднее.

## 7. Командная защита на 5–7 минут

| Время | Что показывать |
|---|---|
| 0:00–0:40 | Проблема: очередь в кафе; кто клиент и кто сотрудник. |
| 0:40–1:10 | Архитектура React → Express → PostgreSQL. |
| 1:10–3:10 | Сценарий клиента и сотрудника из раздела 4. |
| 3:10–4:00 | Последний заказ в базе и один аналитический SQL. |
| 4:00–5:00 | Insights и реальные результаты тестирования, если они проведены. |
| 5:00–6:00 | Картинки, ограничения, smart-функция и вклад каждого. |

Твоя часть, если ты делал интерфейс: Menu, Cart, понятные кнопки, адаптация,
картинки и доступность. Говори “I” о личной работе, “we” — об общей.

## 8. Ответы, которые надо понимать

- **Почему нельзя подменить сумму?** Сервер получает ID и количество, цену берёт из БД и считает итог сам.
  “The server calculates the total using database prices.”
- **Что такое транзакция?** Заказ и позиции сохраняются вместе. При ошибке — ROLLBACK.
  “Either the whole order is saved, or the changes are rolled back.”
- **Как защищён вход?** Хеш bcrypt вместо открытого пароля, JWT на 8 часов и проверка роли на API.
  “Passwords are hashed. Protected API routes check the token and admin role.”
- **Как обновляется статус?** Опрос API раз в 8 секунд, не WebSocket.
- **Есть онлайн-оплата?** Нет: самовывоз и оплата в кафе.
- **Есть IoT или ИИ?** Физического датчика нет. Ожидание — правило: 5 + 3 × очередь, максимум 60 минут; это не проверенный прогноз.
- **Почему доверять графикам?** Можно повторить SELECT в docs/ANALYSIS.sql. Искусственная выборка проверяет метод, не поведение настоящих посетителей.
- **Есть HTTPS?** В стандартном локальном запуске HTTP. В проекте есть дополнительный Caddy-профиль, но без его настройки не заявляй проверенный HTTPS.

## 9. Последняя проверка перед выходом

Пройди заказ от начала до READY, найди его в SQL, открой Insights и media.tsx.
Проверь пароль до выступления. Возьми готовое командное видео как резерв,
если оно есть. Заполни группу, личный вклад и реальные результаты пользовательских
тестов в отчёте. Минимум три внешних тестировщика и три замера Fast 4G нельзя
заменить придуманными цифрами или старыми скриншотами. Подробная форма — docs/TESTING.md.
